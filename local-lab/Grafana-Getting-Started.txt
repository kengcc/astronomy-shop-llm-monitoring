VIEW THE TEST DATA
1. Open your Grafana Cloud stack.
2. Select Observability > Agent > Conversations (or Agent Observability).
3. Set Past 1 Hour, clear filters and refresh.
4. Look for astronomy-shop-lab and open a conversation. Inspect its prompt,
   response, model steps and linked trace. Without an explicit conversation ID,
   Grafana groups compatible spans by trace into separate conversations.
5. Click a sample question at http://localhost:8080/chatbot/ to create more data.

The agent uses recorded model responses, not live inference. Missing token
counts or estimated model costs are expected and must not be treated as real
usage or proof of zero production cost. Tool spans are context; Grafana does
not create standalone generations for tool operations.

CONTROLS
Run these commands from the installation folder.

Enable Grafana export or recreate only its Collector:
  ./grafana.sh up -d --no-deps --pull never --no-build otel-collector
  ./grafana.sh restart agent

Switch back to the saved Datadog route:
  ./datadog.sh up -d --no-deps --pull never --no-build otel-collector
  ./datadog.sh restart agent

Return to local-only telemetry:
  ./lab.sh up -d --no-deps --pull never --no-build otel-collector
  ./lab.sh restart agent

Stop all demo containers:
  ./grafana.sh stop

Avoid running up for the whole stack during controlled testing: it starts the
automatic load generator too. Keep it stopped:
  ./grafana.sh stop load-generator

TEST SCENARIOS
Baseline: use the same three sample questions used for Datadog.
Slow model: http://localhost:8080/feature/ > aiSlowResponse > 5sec. Run one
sample, identify slower model steps, then restore the flag to off.
Unsupported prompt: ask "what's best seller products here?". The agent fails
because no recording is available. Check how clearly Grafana surfaces the
failure; the chatbot displays recovery guidance. A supported sample should
work afterward. Operation filtering can affect where failed generations appear.
