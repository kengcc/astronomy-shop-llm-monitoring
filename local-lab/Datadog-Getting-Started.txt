OPEN AND TEST
1. In Datadog, choose AI Observability > Agent Observability > Traces
   (the product may still be labelled LLM Observability).
2. Set the time range to Past 15 minutes and refresh.
3. Look for app astronomy-shop-lab; try the filter ml_app:astronomy-shop-lab.
   If needed clear filters and look for service agent.
4. Open http://localhost:8080/chatbot/ and click one of its three sample buttons.
5. Refresh Datadog and open the new trace. Inspect the workflow, model steps,
   tool calls, durations and available prompt/response content.

The agent replays recorded model responses. Token usage/cost fields may be
missing. This setup does not evaluate live inference cost or model quality.

CONTROLLED FOLLOW-UP TESTS
Slow model: open http://localhost:8080/feature/ and set aiSlowResponse to 5sec.
Run one sample question; each model step should gain approximately five seconds.
Inspect the delay in Datadog, then restore aiSlowResponse to off.

Error: ask "what's best seller products here?". This has no supported recording.
The chatbot shows recovery guidance; inspect the failed agent/model request in
Datadog. Then click a supported sample question to verify recovery.

RUN AND STOP
From the installation folder, while Datadog export should remain enabled:
  ./datadog.sh up -d --pull never --no-build otel-collector
  ./datadog.sh start agent chatbot
  ./datadog.sh stop load-generator
Do not run datadog.sh up for the whole stack unless you intend to start the
load generator too. Avoid lab.sh up for the Collector while cloud export is
wanted; it uses only the local configuration and replaces the cloud route.

Disconnect Datadog while retaining local observability:
  ./lab.sh up -d --no-deps --pull never --no-build otel-collector
  ./lab.sh restart agent

Stop the entire demo:
  ./datadog.sh stop
